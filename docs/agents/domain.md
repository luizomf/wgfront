# Domain Documentation

This is a **single-context** repository, not a monorepo.

Before exploring a topic, read root `CONTEXT.md` and relevant decisions in
`docs/adr/` if they exist. If `CONTEXT-MAP.md` later establishes multiple contexts,
follow it and read the relevant per-context documents and ADRs instead.

Missing domain documents are not blockers: proceed silently. Producer skills
create them lazily when domain terms or architecture decisions are resolved.
Do not create speculative glossary entries or ADRs merely to complete setup.

Use established glossary terms in issues, code discussions, and plans. Surface
conflicts with existing ADRs explicitly rather than silently overriding them.
Until domain documents exist, use `README.md`, `docs/structure-format.md`, the
accepted issue/conversation contract, and the implementation as context. Historical
research and scripts in `docs/` are references, not authority to operate real hosts.
